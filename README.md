# RoomPlan

Исследовательский web-прототип планирования квартир: Python + Three.js. **Статус: проверенный прототип в согласованном объёме от 16.10.2026.** Результаты Gauntlet Loop, включая найденные ошибки и повторные проверки, — в [итоговом независимом отчёте](artifacts/reviews/acceptance-round7.md) и на `/progress`. Исходное задание — [docs/USER_REQUIREMENTS.md](docs/USER_REQUIREMENTS.md). Сравнение с Floorplanner было неслепым; общее превосходство над продуктом не заявляется.

## Запуск

Требуется Python 3.10+ и современный браузер с WebGL2. Для экспорта видео нужен FFmpeg в PATH (в Docker он устанавливается автоматически). Визуализатор Three.js включён в репозиторий, сборка Node.js и CDN для запуска не нужны.

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python server.py --port 8765
```

В Windows можно использовать `./run.ps1`: скрипт выбирает локальную `.venv`, затем доступный bundled Python Codex, затем `python` из PATH.

Открыть http://127.0.0.1:8765 и http://127.0.0.1:8765/progress . Данные редактируются в браузере; для долговременного хранения скачивайте проект на свой компьютер. Оригиналы изображений и видео входят в архив.

## Структура

- `roomplan/` — модель, распознавание плана, провайдер реконструкции, валидация, архив и экспорт; Python.
- `server.py` — HTTP API и локальная раздача приложения.
- `web/` — интерактивный редактор и визуализатор Three.js; JavaScript необходим для исполнения в браузере.
- `tests/` — проверки модели и обработки данных.
- `docs/quality-bar.md`, `docs/acceptance.md` — фиксированные критерии визуальной и функциональной проверки.
- `artifacts/reviews/` — фактические независимые оценки, включая неудачные итерации.
- `progress.json` — обновляемый журнал для живой страницы.

Видео рендерится последовательностью кадров 1280×720 с частотой 15 кадров/с и кодируется локальным Python-сервером через FFmpeg в WebM. Поэтому медленный рендер увеличивает время ожидания, но не сокращает число кадров ролика.

PNG экспортируется в 1600×1000 независимо от ширины окна редактора. План для объявления сохраняется в SVG. В 2D перемещайте вид левой кнопкой по свободному месту; в 3D для этого есть переключатель «Переместить вид», а вращение и масштабирование доступны мышью.

Визуализация и проход используют обычный растровый рендер Three.js. По уточнению пользователя от 16.10.2026 трассировка лучей и фотореализм исключены из текущего прототипа. Фотореалистичные изображения и видео будут создаваться отдельным модулем с генеративной моделью; граница подключения описана в [docs/GENERATIVE_RENDERING.md](docs/GENERATIVE_RENDERING.md).

## Режимы реконструкции

Изображение плана обрабатывается реальным базовым алгоритмом; масштаб задаётся известной шириной плана, высота — пользователем. Этот прототип не обещает универсального распознавания любых чертежей: ограничения и предупреждения отображаются при импорте.

**Видео → план.** Если настроен сервис реконструкции [roomplan-app](https://github.com/bulatko/roomplan-app) (приватный репозиторий, доступ по запросу), видео помещения (до 100 МБ) отправляется в его HTTP API. Там на GPU восстанавливаются позы камеры и облако точек (beam_rec), стены и комнаты (wallfield P4), мебель, двери и окна (TUN3D). Обработка занимает 10–30 минут, статус обновляется в окне импорта. Если закрыть окно, ожидание прервётся, а при повторном открытии продолжится. Результат конвертируется в редактируемый проект:
- план поворачивается так, что основные стены идут по осям;
- пол и потолок определяются по плотности облака точек;
- предметы ставятся каталожной мебелью с найденными размерами и поворотом;
- проёмы врезаются в стены;
- облако прореживается до 60 тыс. точек и по умолчанию скрыто (включается в «Слои» → «Облако точек»);
- исходный `result.json` сохраняется ресурсом проекта, параметры преобразования — в `provenance.alignment`.

Сам сервис разворачивается отдельно (Docker + NVIDIA GPU); приложение лишь вызывает его API и не тянет зависимостей конвейера. Настройка — переменные окружения или файл `.env` рядом с `server.py` (образец — `.env.example`; переменные окружения важнее файла):

```sh
ROOMPLAN_VIDEO_API_URL=https://plan.example.org:8443   # корень API сервиса
ROOMPLAN_VIDEO_API_TOKEN=...                          # токен пользователя (заголовок X-Token)
ROOMPLAN_VIDEO_API_OPTIONS={"beam_rec":{"target_frames":200}}   # необязательно: опции задачи
```

Токен и видео передаются с каждым запросом, поэтому удалённый сервис принимается только по `https`, с обычной проверкой сертификата. Обычный `http` допускается лишь для loopback: локальный сервис или SSH-туннель. Иначе `/api/health` показывает причину, а видео не отправляется. Без настройки режим «Видео» создаёт явно обозначенную демонстрационную заглушку, как и раньше.

Набор снимков помещения возвращает явно обозначенный синтетический пример с мебелью и облаком точек — согласованная заглушка для дальнейшего подключения исследовательских алгоритмов. Исходные файлы сохраняются независимо от режима.

Реконструкция отдельного предмета предназначена для локального GPU-сервиса Stable Fast 3D. Пользователь согласовал подключение позднее: отсутствие сервиса должно отображаться явно. Модель по фотографии не считается восстановленной до успешного вызова настоящего inference. Протокол — в SPEC.md и комментариях адаптера. Масштаб результата single-image метода нужно уточнять вручную.

## Развёртывание

Для сервера с Docker:

```sh
docker build -t roomplan .
docker run --rm -p 127.0.0.1:8765:8765 --env-file .env roomplan
```

`.env` не попадает ни в git, ни в образ (`.gitignore`, `.dockerignore`).

Для доступа через домен поместите сервис за HTTPS reverse proxy с подходящим ограничением размера загрузок и таймаутом. Это прототип для доверенного пользователя; для общего публичного сервиса потребуются авторизация, лимиты ресурсов и очередь inference. GPU-сервис разворачивается отдельно от интерфейса. Секреты и личные проекты не включайте в исходники.

## Проверка

```sh
python -m unittest discover -s tests -v
```

Прохождение unit-тестов не означает победы над визуальным эталоном. Сравниваются реальные экспортированные планы, dollhouse и интерьеры; статус определяется записями независимых критиков. Все ограничения слепого сравнения должны быть раскрыты.
